### Medium

- **Recovery restores a replaced entry whose deletion failed, including a half-deleted one** (`src/cli/commands/skills/replace.ts:317`)
  - Issue: `replaceSkill` uses the same `.<skill>.wc-backup-<id>` name for the entry moved aside mid-swap (`replace.ts:210`) and for the replaced entry it deletes after the new install checks out (`replace.ts:235-242`). When that deletion fails or is interrupted, `rmSync` may already have removed some files, such as `SKILL.md`. The run reports "installed, but the replaced entry could not be removed … remove it yourself". `recoverInterruptedReplacements` puts back any single backup when the target is free (`replace.ts:309-328`). After `skills uninstall`, which skips hidden entries (`installed.ts` prefix filter), or after the user deletes the skill by hand, the next `skills install` restores the replaced, partially deleted tree. It reports "put back 1 skill(s) that an interrupted install had moved aside", and `--yes` then skips the fresh install because the name is occupied (`install.ts:146-152`). The result is a broken skill, listed as installed, with exit 0. This is the "restore the wrong entry" case. The documentation promises recovery only for "a skill an interrupted install moved aside" (`documentation/available-skills.md:88-90`), not for a replaced entry.
  - Reproduction: `/tmp/wc-p12-probe/probe1.mts` (temp HOME). Run 1 is `install --tool claude --yes --overwrite` with `removeTree` of the backup injected to delete `SKILL.md`, then throw `EACCES`. Next, remove the `work-chronicler-*` entries as `uninstall` does. Run 2 is `install --tool claude --yes`. Observed: "put back 1 skill(s)…", "Skipped 1 existing skill(s)", exit ok, and `work-chronicler-write-resume-bullets/` contains only `notes.md`, with no `SKILL.md`.
  - Fix: Once the new entry verifies in place, rename the backup to a distinct role (for example `.<skill>.wc-replaced-<id>`) before deleting it. If that rename fails, report it with the existing warning. Recovery should never restore a `replaced` entry: it should remove it, or name it as it does today. Keep auto-restore for `backup` only, which then means a moved-aside entry from an incomplete swap. Add a test that injects a partial `removeTree` failure on the replaced entry, frees the name, re-runs `install --yes`, and expects a fresh, verified install with no "put back" message. The same test should fail on the current code.
