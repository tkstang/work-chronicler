#### H1: Preserve old copies when an entire tool skills directory cannot be inventoried

**Location:** `src/cli/commands/skills/migrate.ts:217-219`, with the unsafe removal decision at lines 271-285.

`inventoryEntries` catches every `readdirSync(dir)` failure and continues as if the tool had no installed entries. The new `unchecked` protection applies only after an entry has been enumerated. Consequently, `EACCES` or `EPERM` at the tool's skills root contributes no incomplete-inventory marker, so an old copy can be classified removable while a dependent skill is hidden behind that permission boundary. `skills install --tool claude --method copy --yes` then recursively deletes the old copy and exits successfully. Restoring access to the unselected tool reveals a broken resource symlink and the loss of its only backing helper.

**One-line reproduction:** In a temporary HOME, create a Claude old-name copy plus a verified replacement and a Cursor skill whose helper links into the old copy; chmod Cursor's `skills/` to `000`, install for Claude with `--yes`, then restore permissions: exit 0, old copy deleted, Cursor helper broken.

**Evidence:** A foreground source-level CLI probe at the exact reviewed head reproduced all three outcomes. The readable-directory control retains the copy. The process is non-root, and permissions are restored in `finally`. The blanket catch is also present at ed8b20d, so this is a newly discovered existing m01 defect, not a regression introduced by the three fixes.

**Impact:** Destructive migration can remove the sole user-maintained helper behind another installed skill. This violates Outcome 1's safe migration and the cross-tool dependency guarantee in `documentation/available-skills.md:88-94`.

**Smallest fix:** Distinguish proven absent tool directories (`ENOENT`/`ENOTDIR`) from unreadable or otherwise unknown inventories. Propagate incomplete inventory to the removal planner, retain old copies conservatively, and identify the inaccessible directory in the notice. Add one install-command regression with a dependent skill behind an unreadable tool root and a missing-tool-directory control. This protects a distinct gap: current permission coverage starts inside an already enumerated skill and never exercises failure of the outer `readdirSync`.
