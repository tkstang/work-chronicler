- **H1: Treat permission-denied link resolution as an incomplete scan** (`src/cli/commands/skills/migrate.ts:154`)
  - Issue: `walk` returns success for every `realpathSync` failure. A nested
    resource symlink pointing through a non-searchable parent produces
    `EACCES`, not a dangling target. Its inner dependency on the old skill is
    never visited, yet the entry is marked fully checked. Migration then
    classifies the old skill as removable and recursively deletes it.
  - Impact: `skills install --tool claude --method copy --yes` exits 0 and
    permanently removes the backing helper. Restoring the directory's
    permissions leaves the kept new-name skill broken. This violates p01's
    safe migration outcome and the new documentation's promise to retain old
    names when an installed skill cannot be fully read.
  - Reproduction: a verified new-name copy has `scripts` linked to
    `private-parent/resources`; that directory contains a `helpers` symlink
    into the old copy's `scripts`. With `private-parent` mode `000`,
    resolution throws `EACCES` and the old entry is deleted. With mode
    `755`, the identical dependency is correctly retained.
  - Fix: distinguish proven missing targets from unknown resolution failures.
    Return an incomplete scan for `EACCES`, `EPERM` and other errors that
    prevent inspection, so `unchecked` retains the old entry. Preserve the
    existing genuinely dangling-link behavior.
  - Coverage gap: retain both new tests and add a focused permission-denied
    regression through the install boundary, with a genuinely missing-target
    control. It must assert the old helper remains usable once permissions
    are restored, not merely that installation returns successfully.
