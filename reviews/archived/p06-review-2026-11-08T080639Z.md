### Fix-delta adversarial checks (no defects found)

- **Value comparison: real changes wrongly treated as no-ops.** Every `applyChange` branch (`slack-config.ts:179-270`) mutates the cloned value in lockstep with the document: new section, workspace or user update, remove, add with absent or empty `channels`. A change therefore always makes `expected` differ from `current`. The remaining `next === text` branch now refuses instead of reporting success (`config-file.ts:169-171`), so a doc/value divergence cannot be silently dropped. Probes: a real add, a real remove (IC), and the last-channel remove (manager report) all reported `changed: true` and changed the file. A different `reason` on an existing channel and a user change while channels exist were refused with exit 1 and bytes unchanged. Manager mode: same-value add, same-value configure (`changed: false`, unchanged) and unlisted remove (refused, unchanged) behaved as in IC mode.
- **nlink refusal: false refusals.** The check lives only in `readConfig` inside `updateConfigFile`, which only the Slack mutators call. `slack show` and `slack channels list` still work on a hard-linked config. A normal config (nlink 1) and a config reached through a symlinked parent directory (`-c <symlinked-dir>/config.yaml`) were updated normally. No code path in `src/` hard-links a config (`fs.link` is used only by the import transaction for its lock and staged records).
- **container.name rule.** `null` and the exact configured name are accepted. A `#`-prefixed name and a case-variant name are refused. This is intended: config names cannot start with `#` (`slack.ts:46-51`), and the journal's p07 note says the skill copies `name` from `slack show`. The error names only the field. For an unconfigured channel the name is no longer checked, but the record is already refused on `message.container.id`, so nothing is stored.
- **Docs.** `documentation/commands.md:213,300,312-314,321` match the new behavior. No stale claim that removing an unlisted channel "changes nothing" remains in the docs, README or CHANGELOG.
