## Purpose

Lets skills hand imported evidence to work-chronicler, and adds Slack as the first source, so self-reviews, resumes and review packets can cite the subject's own Slack messages next to PRs and tickets. Released as 0.6.0. Second of three milestones (m01 shipped 0.5.0; Google Docs follows in 0.7.0).

## Changes

- **Import contract:** `work-chronicler import <dir>` and `work-chronicler validate` check a staged batch of records against a shared envelope and store it all or nothing, with crash recovery. A record that cannot be proven safe (path, identity, subject, replacement) rejects the whole batch. One shared work-log lock serializes imports and `filter` runs.
- **Consumers:** `status`, stats, `filter`, `link` and the MCP server read imported `messages` (new read-only MCP tool `search_messages`) or say they cover PRs and tickets only. Mentions resolve to PRs and tickets on read and are never stored as links. `filter` replaces the subset completely or not at all; the MCP server resolves the selected subset on every call.
- **Slack settings and commands:** `slack configure`, `slack channels add|remove|list` and `slack show --json`, per IC profile and per manager report. Config edits are atomic and keep comments.
- **Slack privacy at the import boundary:** only the configured subject's verified messages from configured channels; DMs and group DMs refused; private channels only when marked; manager-mode report channels only when confirmed as shared; no reply bodies, participant lists, parent text or raw Slack markup.
- **Skills:** `work-chronicler-setup-slack` and `work-chronicler-import-slack` (read-only through the assistant's Slack connector). The writing and detection skills cite imported messages as supplementary evidence.
- **Installer:** `skills install --overwrite` stages and verifies each replacement before touching the installed skill, and puts it back on any failure.
- **Release:** version 0.6.0 and CHANGELOG.

## Notes

- Independently reviewed per phase (Claude) and as a milestone (Codex), with a Codex exit gate. Most findings were filesystem edge cases in the import transaction and locks; each was fixed with a regression test.
- Deferred, tracked in the OAT project: `filter --clear` can report success while readers stay blocked after two consecutive disk faults (to be fixed when `filter` gains Google Docs in 0.7.0); smaller cleanups from the 0.5.0 review.
- Known limit: Node has no `openat`/`renameat2`, so a swap in the instant between the last check and a rename is not detectable. Every earlier substitution is refused.
