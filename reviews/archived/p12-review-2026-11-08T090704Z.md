### Low

- **A replaced entry whose rename to `wc-replaced` fails stays a `wc-backup`: the next install keeps it, then later puts it back, contrary to the docs** (`src/cli/commands/skills/replace.ts:244`)
  - Issue: If `fs.rename(backup, replaced)` throws (`replace.ts:246`), `doomed` stays `backup`. Nothing is deleted, which is correct and safe. The warning then reads "installed, but the replaced entry could not be removed and is left at `.<skill>.wc-backup-…`; remove it yourself" (`replace.ts:250-252`). The docs say a replaced entry that cannot be removed is removed by the next install (`documentation/available-skills.md:84-88`). The next install does not remove it. While the name is occupied, it reports the entry as "an interrupted install left a replaced entry … remove it once you no longer need it" (`replace.ts:351-354`). Once the name is freed (`skills uninstall` skips hidden entries, or the user deletes the skill by hand), the next install puts it back (`replace.ts:334-343`). It reports "put back 1 skill(s) that an interrupted install had moved aside", and with `--yes` skips the fresh install. The result is a working copy, so this is not the round-1 broken-skill case. But it is the pre-overwrite version the user explicitly replaced, and it comes back with a message that says an install was interrupted. A SIGKILL just before this rename (crash pass k=7) leaves the same state. Recovery cannot tell it apart from a kill before the in-place check (k=6), so the code cannot fully disambiguate it. Only the prose overstates.
  - Reproduction: `npx tsx /tmp/wc-p12-probe2/renamefail.mts` (temp HOME). Run 1 is `install --tool claude --yes --overwrite` with the rename to `.wc-replaced-` failing with EBUSY. Run 2 is `install --yes`. Then remove the `work-chronicler-*` entries and do run 3, `install --yes`. Observed: run 2 names the `.wc-backup-` entry and does not remove it. Run 3 prints "put back 1 skill(s)…" and "Skipped 1 existing skill(s)", and the installed `SKILL.md` body is `OLD-USER-EDIT`.
  - Fix: Align the prose; do not try to delete in this branch. Deleting at the backup name would bring back M1. In `documentation/available-skills.md:84-91`, say that if the old entry cannot even be renamed to `wc-replaced`, it is left as `.<skill>.wc-backup-…`. It is then handled like a moved-aside skill: named while the skill is installed, and put back if the name is later free, so remove it as the warning says. Optionally, extend the `replace.ts:251` warning in that branch to say the next install will treat it as a moved-aside copy and may put it back.
