### High

- **H1: Preserve old copies used through nested resource symlinks** (`src/cli/commands/skills/migrate.ts:167`)
  - Issue: `inventoryEntries` records only the skill root's and `SKILL.md`'s
    resolution trails. It never inspects nested `scripts/`, `references/`, or
    resource symlinks. A valid new-name directory whose `scripts` points to the
    old copy's `scripts` therefore looks independent. `planRenamedSkillRemoval`
    marks the old copy removable, and `removeRenamedSkill` recursively deletes
    it at line 238.
  - Impact: `skills install --tool claude --method copy --yes`, without
    `--overwrite`, can keep a customized replacement, delete its backing
    helper files and exit 0. The retained skill then has a dangling resource
    link. The same inventory omission applies to another tool's installed
    skill. This defeats the documented dependency-preservation guarantee and
    destroys the only local copy of those helpers.
  - Reproduction: The temporary-home CLI probe below observed a usable helper
    before installation, `exit: 0`, `oldAfter: false`, and `helperAfter: false`.
    The independent replacement control remained removable as expected.
  - Fix: Include nested symlink dependencies when deciding whether an old
    entry can be deleted, with cycle handling and conservative retention when
    a dependency cannot be checked. Keep and report any old entry used by a
    retained skill. Add a regression at the CLI migration boundary with a
    nested-resource dependency and an independent-resource control.
  - Requirement: Outcome 1 and the migration safety contract in Approach;
    `documentation/available-skills.md:90` promises preservation while any
    installed skill resolves into the old entry. The journal already lists
    the nested-resource omission as deferred under PR comment 4504866395.
    The reproduced destructive effect makes that deferral unacceptable for
    this release; fix it before merge.
