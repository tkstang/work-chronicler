### High

- **H1: Migration can delete the directory backing the verified replacement** (`src/cli/commands/skills/migrate.ts:83`). `isVerifiedSkill` follows both directory and `SKILL.md` symlinks, then removal planning treats a matching name as independent proof that the old copy is disposable. If a user has already exposed the new name through a symlink to the old directory and updated its frontmatter, `skills install --tool claude --method copy --yes` skips that working replacement, deletes the old directory, and exits zero with the replacement dangling. The reviewer reproduced this with the built CLI. An independent new-name symlink survived the same command, so the failure depends on the deletion relationship. Before approving removal, establish that the replacement and its required files do not depend on a path being removed, or install an independent replacement first. Add a migration regression with a dependent replacement link and a valid independent-link control; retain the old copy when independence cannot be established.

- **H2: Owner-lookup rate limits bypass the fatal review-fetch path** (`src/cli/commands/fetch/github/github-reviews.utils.ts:484`). The new review fetch calls shared `isUser` before its search error handler. That helper catches every lookup error and returns `false`, including HTTP 429 and rate-limited HTTP 403. A reviewer HTTP-boundary probe returned 429 for `/users/acme`; fetching still called `/search/issues`, resolved successfully and returned `problems: []`. This breaks the declared stop-on-rate-limit contract and can also choose `org:` for a personal owner after a transient lookup failure. Propagate rate-limit errors through `handleRateLimitError`, and distinguish a confirmed owner classification from an unavailable lookup. Cover a rate limit at this first request and assert that no search or subsequent owner request occurs; retain valid user and organization controls. Existing tests only cover rate limits during search and review listing.

### Medium

- **M1: The no-overwrite path deletes a regular-file conflict** (`src/cli/commands/skills/install.ts:335`). Conflicts come from `findInstalledSkills`, which omits regular files. During an upgrade, an old-name directory plus a file at `work-chronicler-write-resume-bullets` therefore yields zero conflicts; `overwrite` becomes true even with `--yes` and without `--overwrite`. The actual CLI deleted the file's sentinel content, installed over it, removed the old copy and exited zero. A same-name directory control preserved its content. The new conflict filtering excludes the old directory that previously forced the refusal path. Determine conflicts from occupancy of every intended destination, and grant replacement permission only from an explicit overwrite decision or the documented broken-link repair. Add the regular-file case beside the existing directory-conflict test.

- **M2: Stored review records are reused across reviewer identities** (`src/cli/commands/fetch/github/github-reviews.utils.ts:339`). Existing records are keyed only by PR and are used for cache checks and merging without checking `existing.reviewer`. Changing `github.username` while reusing the output directory can skip the new person's fetch entirely under `--cache`. Without cache, changing the date range retains the previous person's out-of-range entries and writes `reviewer: <new person>` over them. The reviewer seeded an Alice record, fetched Bob's May range and observed Alice's February review under `reviewer: bob`; the cache control kept the Alice record without listing Bob's reviews. Require a case-insensitive reviewer identity match before cache reuse or merging. On mismatch, either refuse with actionable guidance or replace/isolate the record without attributing the previous subject's entries to the current subject. Test both cache and different-range paths.
