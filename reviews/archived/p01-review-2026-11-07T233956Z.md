- **Upgrade notes do not warn that `--yes` deletes old-name copies including local edits** (`documentation/available-skills.md:81`)
  - Issue: For unchanged names, `--yes` keeps existing skills so local edits survive. For renamed skills, `--yes` recursively deletes the old-name copy (`migrate.ts:100-101`) once the new name verifies, so any edits the user made to the old copy are lost without a prompt. The brief allows this, because old-name content may be removed once the replacement exists. The asymmetry is not stated in `available-skills.md`, the CHANGELOG entry or the `--yes` help text (`install.ts:294`).
  - Fix: Add one sentence to the upgrade notes and the CHANGELOG entry: "Old copies are deleted, including any local edits; use `--keep-old` to keep them."

  - Issue: `reports add` defines only `--github`, `--email`, `--repos` and `--jira-projects` (`src/cli/commands/reports/add.ts:21-24`), so Commander rejects `--skip-fetch` as an unknown option. The flag predates this phase (it is present at base `a3b950d`). This phase repositioned the skill for IC users, though, and an IC user who picks "Add as report" will hit the error. It also breaks the AGENTS.md rule that every flag named in a skill must exist in `src/`. A smaller wording drift in the same skill: lines 34-37 label `workspace root` as "Manager root" / "your manager profile path" even though quick mode now runs in IC profiles.
  - Fix: Drop `--skip-fetch` from line 128, or use `reports add "<Their Name>"` to match the `[name]` argument. Optionally relabel "Manager root" as "Profile root".
