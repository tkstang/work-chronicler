### High

- **H1: Rollback cleanup follows a substituted ancestor outside the work log** (`src/core/import/transaction.ts:646`)
  - Issue: `createdDirectories` contains every planned missing directory, including directories whose creation never succeeds. Cleanup reverses that list and calls `rmdir(root/...segments)` without checking ancestor type or ownership. If `messages` becomes a symlink just before its mkdir, the commit detects it at line 992 and rejects, but rollback first traverses that symlink to delete an existing external `slack/` directory.
  - Reproduction: The isolated hook inserts `messages -> outside` immediately before `mkdir(messages)`. The result is `ok:false` with `CHANGED_DURING_IMPORT`, while `outside/slack` is gone. A normal import keeps the external directory. This is a deterministic concurrent-change probe, not a demonstrated attack from staged record text.
  - Impact: A correctly detected unsafe destination still causes mutation beyond the configured root. The demonstrated deletion is an empty directory; this probe does not claim deletion of nonempty external content.
  - Fix: Apply root/component containment checks during cleanup and remove only directories whose successful creation and identity are established. Recovery must refuse ambiguous directory ownership and preserve its journal instead of treating all planned paths as owned.
  - Requirement: p04 fail-closed containment, safe rejection and changing-path threat cases T8/T12/T14.

- **H2: Recovery consumes backup files through an already symlinked transaction directory** (`src/core/import/transaction.ts:603`)
  - Issue: Recovery validates the transaction root but never validates its `backup` ancestor before reading and renaming `backup/0.md`. `O_NOFOLLOW` on the final file does not prevent following an intermediate directory link. The old-content hash verifies bytes, not containment.
  - Reproduction: Interrupt a two-record update immediately after the first destination rename, move `.import-transaction/backup` to an external directory, and replace it with a symlink. An empty-batch recovery returns `ok:true` and `rolled-back` while consuming external `backup/0.md`. The link exists before recovery starts, so this is not the documented final-check-to-mutation race.
  - Impact: Recovery reports success while moving a file from outside its trusted transaction tree. The probe uses a relocated authentic backup with the required old hash; it does not claim arbitrary-byte injection.
  - Fix: Before any recovery mutation, validate the transaction subdirectories and all source/destination components, including directory identity and containment. Refuse symlinked, replaced or unreadable recovery state with `RECOVERY_CONFLICT` and preserve external files and the transaction.
  - Requirement: p04 T8/T14/T17 and rejection whenever containment or safe replacement cannot be established.

### Medium

  - Issue: The new message tool reads the directory captured by `createServer` at startup. Its `subsetGapNote` returns immediately when that captured directory equals the full root. Selecting a subset after startup therefore leaves the handler reading the full log. The same fixed context is passed on every tool call at `src/mcp/server.ts:120`.

The same client still sees one message; restarting the server sees zero. A server already bound to the subset also returns an ordinary empty result after that directory is moved into an interrupted-swap state.

  - Fix: Resolve and validate effective subset state from the stable full root at each request, centrally for every tool, or reject calls when the captured selection is stale. Add a same-client transport regression covering full-to-subset, subset-to-full and interrupted replacement.
  - Requirement: p05 and Outcome 4, selected subsets must never be silently bypassed.
